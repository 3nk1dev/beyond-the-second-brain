# Publication checklist

This is a review list, not authorization to publish.

- [ ] Confirm the new repository name and owner.
- [ ] Confirm public or private visibility explicitly; keep private until resolved.
- [ ] Review GUIDE.md and the templates for accuracy and tone.
- [ ] Remove any private paths, repository addresses, credentials, client material, or unapproved personal information from both files and history.
- [ ] Decide whether the public author profile and any official website links are accurate and approved.
- [ ] Choose the rights or license deliberately; do not add one by default.
- [ ] Verify relative links and Markdown formatting.
- [ ] State that templates are illustrative, not a packaged implementation.
- [ ] Approve publication separately from drafting.
- [ ] After an authorized push, inspect the remote branch and intended visibility.
- [ ] Back up the current public profile README and profile text before editing them; record their source and observation time.
- [ ] Inspect proposed profile changes and titles without exposing the private vault.
- [ ] Verify the resulting public profile and repository links after authorized changes.

A local file or a push is not proof that a profile was updated. Record blocked and unverified steps honestly.
